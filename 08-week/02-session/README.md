\# Week 08 - Session 02



\## Story Mapping, Estimation and MVP 2 Commitment



This session focused on planning a realistic MVP 2 through story mapping, relative estimation and dependency management.



\### Main concepts



\- Story mapping based on the end-to-end user journey.

\- MVP 2 release line to separate committed work from later work.

\- Relative estimation using story points.

\- Fibonacci scale: 1, 2, 3, 5, 8 and 13.

\- Large stories must be split before commitment.

\- Planning Poker for shared estimation.

\- Cross-service dependency identification.

\- Contract-first development.

\- Mocks and stubs to avoid blocking teams.

\- Commitment based on real team velocity.



\### Planning flow



User Journey → Story Map → Estimation → Dependencies → MVP 2 Scope → Sprint



\### Application to OptiView



OptiView requires coordination between multiple services and repositories. Stories must therefore be organized around a complete user journey instead of isolated functionality.



Dependencies between services should be identified before implementation. Contracts and mocks allow teams to work in parallel without waiting for another service to be completed.



The MVP 2 scope should contain only work that can realistically be completed according to team velocity and the Sprint Goal.



\## Key takeaway



A small, complete and integrated MVP is preferable to a larger set of partially completed features.
